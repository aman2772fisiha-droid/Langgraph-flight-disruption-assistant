Flight Disruption Rebooking Assistant
An autonomous multi-agent disruption response system built with LangGraph. When an airline flight is cancelled or delayed, this assistant parses passenger messages, categorizes intent, extracts operational constraints, coordinates with specialists to produce compliant resolutions, verifies those resolutions against strict airline policies using a deterministic rule engine, and provides multi-turn continuity via conversational checkpointing.

It includes an interactive Human-in-the-Loop (HITL) supervisor review stage using modern LangGraph interrupt() and Command(resume=...) primitives for financial payouts exceeding $300.

2. Core Node Responsibilities
Node Name	Component Type	Responsibility
classifier	LLM / Classifier	Parses the passenger message into a structured intent (rebook, refund, compensation, complaint) and extracts domain constraints (e.g., arrival deadlines). Pre-populates booking details from storage.
rebooking_agent	LLM + Tool Loop	Orchestrates flight search. Issues tool calls to inspect available inventories, analyzes arrival constraints, and outputs a concrete ProposedSolution payload.
rebooking_tools	ToolNode	Executes tools (search_flights, get_booking) generated by the Rebooking Agent and returns structured ToolMessage payloads into state.
refund_agent	Specialist Agent	Resolves refund queries. Differentiates between involuntary airline cancellations (full fare refund) and voluntary passenger cancellations on non-refundable tickets (taxes-only).
compensation_agent	Specialist Agent	Evaluates statutory disruption compensation based on delay duration ($0 for <3h, $200 for 3–6h, $400 for >6h or cancellations).
policy_checker	Zero-LLM Rule Engine	Validates solutions against mandatory airline rules using pure Python logic. Increments retry_count on rejection and provides structured feedback reasons back to agents.
supervisor_approval	Human-in-the-Loop (interrupt)	Pauses graph execution when payouts exceed $300. Saves checkpoint state and prompts an operator via the terminal to approve (y) or reject (n) with operational exceptions (e.g., weather).
escalation_node	Escalation Specialist	Compiles a structured handover ticket summarizing passenger details, failure reasons, attempts made, and recommended human actions when retries exhaust or complaints occur.
final_response	Response Synthesizer	Formulates a passenger-facing message detailing flight itineraries, refund timelines, compensation confirmations, or human handover notices.
3. State Design (state.py)
The system uses a centralized, typed state implemented via Python's TypedDict. State mutation is governed by explicit functional contracts:

Python
from typing import Annotated, Any, Dict, List, Literal, Optional
from typing_extensions import TypedDict
from langchain_core.messages import AnyMessage
from langgraph.graph.message import add_messages

class ProposedSolution(TypedDict, total=False):
    type: Literal["rebook", "refund", "compensation"]
    flight_number: Optional[str]
    cabin_class: Optional[str]
    departure_time: Optional[str]
    arrival_time: Optional[str]
    connection_time_mins: Optional[int]
    hours_from_disruption: Optional[int]
    amount: Optional[float]
    details: Optional[str]

class RebookingState(TypedDict):
    # Message history with built-in reducer
    messages: Annotated[List[AnyMessage], add_messages]
    
    # Request metadata & Classification
    request_id: str
    booking_ref: str
    intent: Optional[Literal["rebook", "refund", "compensation", "complaint"]]
    constraints: Dict[str, Any]
    
    # Domain Data & Proposed Resolutions
    booking_details: Optional[Dict[str, Any]]
    proposed_solution: Optional[ProposedSolution]
    
    # Policy Enforcement & Loop Counters
    policy_passed: Optional[bool]
    policy_failure_reason: Optional[str]
    retry_count: int
    
    # Human-in-the-loop & Escalation
    supervisor_approved: Optional[bool]
    supervisor_notes: Optional[str]
    is_escalated: bool
    escalation_handover: Optional[str]
    
    # Passenger Facing Response
    final_response: Optional[str]
Why this design?
Reducers (add_messages): Preserves conversation history across turns rather than replacing it. Follow-up messages append naturally without erasing context.

Selective Delta Updates: Nodes return partial dictionary updates. A node modifies only its assigned keys (e.g., policy_checker only updates policy_passed, policy_failure_reason, and retry_count), preventing cross-agent state contamination.

Typed Solution Payloads: The ProposedSolution schema provides a consistent contract for both automated validators and human reviewers.

4. Routing Decisions & Conditional Logic (graph.py)
Routing is decoupled from worker nodes and handled exclusively by 4 conditional edge functions:

route_intent (Intent Router):
Evaluates state["intent"] to route from classifier to rebooking_agent, refund_agent, compensation_agent, or escalation_node.

route_rebooking_output (Tool Execution vs. Evaluation):
Checks the most recent message from rebooking_agent. If tool_calls are present, execution branches to rebooking_tools. Once the agent issues its final answer, execution proceeds to policy_checker.

route_policy_result (Policy Engine & Retry Cycle):

If policy_passed == True and payout >$300→ routes to supervisor_approval.

If policy_passed == True and payout ≤$300 (or flight rebooking) → routes to final_response.

If policy_passed == False and retry_count < 3 → loops back to rebooking_agent with failure feedback.

If policy_passed == False and retry_count >= 3 → routes to escalation_node (guaranteeing loop termination).

route_supervisor_decision (HITL Gateway):
Checks state["supervisor_approved"]. If approved, branches to final_response; if rejected, diverts to escalation_node.

5. Policy Rules Engine
The policy_checker is a pure Python node with zero LLM dependencies to eliminate hallucinations and enforce strict business logic:

Rebooking Validation:

Cabin Rule: Proposed cabin rank must be less than or equal to the booked cabin (economy cannot be upgraded to business).

Schedule Window: New flight departure must occur within 48 hours of original disruption.

Connection Minimum: Any layover must provide at least 60 minutes connection time.

Refund Validation:

Involuntary airline cancellations must receive a 100% full fare refund.

Voluntary requests on non-refundable tickets are limited strictly to recoverable taxes.

Compensation Rules (Statutory Payouts):

Delays under 3 hours: $0

Delays between 3 and 6 hours: $200

Delays over 6 hours or cancellations: $400

6. Mock Tools (tools.py)
Three deterministic mock tools eliminate external service dependencies and provide repeatable test paths:

get_booking(booking_ref): Retrieves passenger details, itinerary, ticket fare class, and cancellation/delay status.

search_flights(origin, destination, date): Returns available flights. Contains a deterministic violation case (ORD → NRT returns only business-class seats) to validate retry cycles.

get_fare_rules(fare_type): Returns fare rules, base ticket value, and refundable tax balances.

7. Checkpointer & Session Persistence (MemorySaver)
The graph compiles with LangGraph's MemorySaver:

Python
memory = MemorySaver()
app = builder.compile(checkpointer=memory)
Conversations are isolated by thread_id via {"configurable": {"thread_id": "..."}}:

Multi-Turn Continuity: When a passenger submits a follow-up query on thread_s1 (e.g., "Actually, can I get a refund instead?"), the state is loaded from the checkpointer. The assistant references the stored booking reference (XK9L2P) and disruption records without asking the passenger to resubmit their details.

Interrupt Checkpointing: When interrupt() fires for supervisor review, execution halts and saves state to MemorySaver. When resumed using Command(resume=...), execution restores from the exact interruption point.
